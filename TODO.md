### iPhone and Watch

- [ ] **Smart trainers on the iPhone, and what's left of the sensors.** Bluetooth LE sensors are done on the iPhone (`Headwind/Sensors/`, `Shared/GATT.swift`: Cycling Power, Speed and Cadence, Heart Rate, Fitness Machine) and on the Watch (HealthKit's `cyclingPower` / `cyclingCadence`); power and cadence go up in the GPX, which `parse_gpx` already reads. iPhones and the Watch have no ANT+.
  - [ ] Add byte strings captured from real sensors to the parsing tests (log `characteristic.value` in `SensorManager`), since devices differ in which optional fields they send.
  - [ ] A wheel sensor as a check on GPS distance in a tunnel, and the wheel circumference per bike on the server (it's on the phone now).
  - [ ] Power on each point is the 3 s average, not the latest reading as the Watch's is: smoother in the GPX, but the server's 1 s and 5 s best powers come out a little lower. Add the latest reading to `SensorReadings` for the points if that matters.
  - [ ] Turbo trainer: an indoor ride with no GPS (the timer-only mode is done: `Sport.indoorRide`, uploaded to `/api/v1/activities` as `VirtualRide`), distance and speed from the trainer or a speed sensor. Later, ERG mode: set a target power through the Fitness Machine control point.
    - [ ] **An indoor ride with its data:** the trainer's power, cadence, speed and distance (Indoor Bike Data) recorded every second. With readings it goes up as a file, not a bare session: a GPX with no positions can't carry them, so write a TCX (`<Trackpoint>` with time, distance, cadence and heart rate, and power in the ActivityExtension `<Watts>`, which `parse_tcx` reads) or a FIT file, and post it to `/api/v1/rides` as `VirtualRide`. Check the server keeps it indoor (no weather, no map, its own best times: `services/sports.is_virtual`).
    - [ ] **Smart-trainer control (Fitness Machine Control Point, 0x2AD9):** request control (op code 0x00) and start (0x07); wait for each write's indication (0x80 with the op code and a result) before the next. **ERG mode:** set target power (0x05, watts as signed 16-bit), held by the trainer whatever the cadence. **Resistance:** set target resistance level (0x04). **Simulation:** indoor bike simulation parameters (0x11: wind speed, grade in 0.01 %, rolling resistance, wind resistance), for riding a route's gradients. Read Fitness Machine Feature (0x2ACC) and Supported Power / Resistance Range (0x2AD8 / 0x2AD6) first, and offer only what the trainer supports. Stop or reset (0x08 / 0x01) at Finish, and on a dropped connection fall back to the trainer's own free-ride mode.

## Not doing

Decided against, with the reason, so they aren't looked into again.

- **Garmin's official sign-in.** Its OAuth (the Connect Developer Program) is for businesses only, and pushes data to a public HTTPS address on each server, so it doesn't fit a self-hosted app (decided 2026-10-20). Headwind signs in through garminconnect and keeps only its tokens.
- **OS Leisure maps.** The OS Maps API publishes it only in British National Grid (EPSG:27700), and its useful zooms (6-9) are Premium. Every map here is Web Mercator; Leisure would need Proj4Leaflet and a map in 27700 of its own. OS Outdoor in 3857 is used instead, on the OpenData zooms only.
